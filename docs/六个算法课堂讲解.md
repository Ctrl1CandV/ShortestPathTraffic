## 1. Warshall 算法：怎样从直接关系得到传递闭包？

### 先分清三张表

集合上的二元关系 `R` 可以画成有向图：`(i,j)∈R` 就画 `i→j`。关系矩阵 `M_R` 中第 `i` 行、第 `j` 列为 1，表示这条**直接关系**存在。若能沿 `i→k→j` 走到 `j`，即使 `M_R[i,j]=0`，`i` 到 `j` 也是可达的。

- §1.2 的**传递闭包** `t(R)` 是包含 `R` 的最小传递关系。`(i,j)∈t(R)` 表示可以从 `i` 沿至少一条有向边走到 `j`。如果 `i` 没有自环，也没有绕出去再回来的路，闭包的第 `i` 个对角元就是 0。
- §2.3.5 的**可达矩阵** `P` 对不同顶点判断是否可达，并规定 `P[i,i]=1`。相当于允许不走边就到达自己。因此用同一套算法求 `P` 时，初始化多一步：把对角线置 1。

### 为什么要一轮只放开一个中间顶点？

给顶点编号 `1,…,n`，定义 `M⁽ᵏ⁾[i,j]` 表示从 `i` 到 `j` 是否有一条走法，沿途的**内部顶点**只取自 `1,…,k`。起点和终点本身不受这个编号范围限制。没放开任何内部顶点时，只能靠直接边（求 `P` 时再允许长度为 0）。放开第 `k` 个顶点以后，有两种可能：

1. 不经过 `k` 当中间顶点，上一轮已经可达。
2. 经过 `k` 当中间顶点，可以拼接上一轮已有的 `i→…→k` 与 `k→…→j`。若一条走法多次把 `k` 当作内部顶点，就在第一次和最后一次内部出现的位置截取前后两段，略去中间绕回 `k` 的部分。

所以 `M⁽ᵏ⁾[i,j] = M⁽ᵏ⁻¹⁾[i,j] ∨ (M⁽ᵏ⁻¹⁾[i,k] ∧ M⁽ᵏ⁻¹⁾[k,j])`。反过来，这两种情况也都确实能得到一条允许的走法。处理完 `n` 轮后，所有内部顶点都已放开，答案就全了。

教材把公式写成行运算：检查第 `k` 列。若某行第 `k` 格为 1，就把第 `k` 行按位「或」到这一行。第 `k` 行不会因与自己做「或」而改变；第 `k` 列中为 0 的行本轮不会更新，为 1 的格子也不会变回 0。因此可以在同一张表上改，不用存前后两份。

```text
M ← 关系矩阵；若求教材定义的可达矩阵，则对角置 1
对 k = 1,…,n：
    对每个 i：
        若 M[i,k]=1，则对每个 j 更新 M[i,j] ← M[i,j] ∨ M[k,j]
返回 M
```

外层要遍历中间顶点 `k`，这样每轮读到的才是上轮已经求全的关系。最坏时间为 `O(n³)`，矩阵占 `O(n²)` 空间。

### 教材例 1.2.15：盯住第二行

初始矩阵按 `a,b,c` 排列，三行分别为 `111 / 100 / 001`。放开 `a` 时，第二行的首格为 1（`b→a`），所以第二行与第一行做「或」：`100 ∨ 111 = 111`。其中 `b→c` 来自 `b→a→c`，`b→b` 来自 `b→a→b`。再放开 `b`、`c` 都不产生新的 1，最终三行是 `111 / 111 / 001`。原题没有预填对角线，第二个对角元确实是本轮算出来的。

容易被追问：**能不能从最终矩阵读出最少经过几条边？** 不能。每格只存有或无，直达与绕三步都是 1。

## 2. 最邻近方法：它构造的是哈密顿圈，还是最优哈密顿圈？

教材 §2.4.2 给出**哈密顿路**和**哈密顿回路**：前者经过每个顶点恰好一次；后者还要求闭合，写序列时把起点写在末尾只是为了表示回到起点。欧拉回路恰好走遍的是每条**边**，两者不能混用。§3.6 的旅行售货员问题（TSP）要求在**加权完全无向图**中找边权和最小的哈密顿圈。存在一条巡回路线和证明它最短，是两个要求。

固定出发点后，剩下 `n−1` 个点有 `(n−1)!` 种排列。在无向图里，正反走法是同一圈，`n≥3` 时有 `(n−1)!/2` 个不同的圈。这解释了教材为什么引入近似做法：不枚举每一圈，只按一个局部规则快速构造候选路线。

### 只从路径的尾端往外接

```text
任选起点 s（题目指定起点时用指定的），当前点 x ← s
未访问集合 U ← V 去掉 s，路径 ← [s]
当 U 非空：
    在 U 中取使 w(x,y) 最小的点 y；若并列，可约定按编号取一个
    把 y 接到路径末端，从 U 删掉 y，令 x ← y
加入边 x—s，输出闭合路线，含返程边的边权和
```

每步找的是**离当前尾点最近的未访问顶点**，不是把所有点按离起点的距离排好。也别和教材下一种最邻近插入法混淆：插入法每轮都维护一条闭合路线，要考虑把新点插在哪个位置。这里直接扫描未访问点找最小权，总共检查 `(n−1)+(n−2)+…+1` 个候选，时间 `O(n²)`，额外只需记录访问状态和路线。

### 教材例 3.6.1：同一张权图算出 55 和 42

按图 3.6.1 从 `A` 起步：先取权为 2 的 `AD`。到了 `D`，`A` 已不可选，在剩余点中以 `DC` 的 9 最小；到了 `C`，再取 `CB` 的 3。接下来选 `BE` 的 12，只剩 `F`，最后回到 `A`。

| 出发点 | 算出的闭合路线 | 各段权值相加 |
|---|---|---|
| `A` | `A→D→C→B→E→F→A` | `2+9+3+12+13+16 = 55` |
| `C` | `C→B→A→D→E→F→C` | `3+6+2+13+13+5 = 42` |

### 能保证什么？

每步删掉一个未访问点，因此不重访；完全图保证每一步的连接边和最后回起点的边都存在，因此能得到一个合法圈。可是 `w(x,y)` 最小只说明**这一段**省，不涉及其余点怎么串起来，也不考虑返程。表中 42 的圈可以从 `A` 开始写成 `A→D→E→F→C→B→A`，所以即使出发地固定为 `A`，55 仍不是最优；无需知道 42 本身是不是最优就能反驳。若图不是完全图，贪心走到一半接不上也不代表原图不存在哈密顿圈。

抽查时可以拿这两圈说明：**TSP 是优化问题，最邻近是求可行近似解的启发式方法。** 不要把「每轮取最小」说成「总权一定最小」。

## 3. Dijkstra 算法：哪个暂定距离已经不可能再降？

给定源点 `s`，一条路径的长度是沿途边权之和。`δ(s,v)` 表示从 `s` 到 `v` 的最短距离，不可达记为 `∞`。教材先用正权图介绍算法，再在第 91 页展示有向带权图；下面的证明只需要边权**非负**，所以零权也允许。有向图中只沿允许的方向走。

### 两组顶点和一次松弛

教材把顶点分成两组。已定型集合 `S` 中，标号 `l(v)` 已经等于 `δ(s,v)`；其余顶点的 `l(v)` 是目前发现的最短长度，仍可能降低。更准确地说，一轮更新结束后，未定型点的标号是内部顶点都在 `S` 的路线里最小的长度（尚未发现这样一条路线时为 `∞`）。把 `u` 加入 `S`，就用它试着改善邻点 `v`：

`l(v) ← min(l(v), l(u)+w(u,v))`

比较的是**从同一个源点累计的代价**。若真的变小，记下 `v` 的前驱 `u`，最后沿前驱逆向找回源点，再反转就是路径。

```text
S ← 空集；l(s) ← 0，其余标号为 ∞
从 V−S 取标号最小的顶点 u；若没有有限标号，结束
把 u 加入 S；若只求一个终点且 u 正是终点，可在此结束
扫描 u 指向未定型点 v 的边，尝试松弛并记录前驱
重复取最小、定型、松弛，直到结束
```

### 为什么最小的那个可以定型？

边权非负，源点到自身的最短距离是 0，所以第一步定型正确。假设此前定型的标号都正确，这一轮选了 `u`，却有一条更短的 `s→…→u`。在那条路上找**第一个还不在 `S` 里的点** `x`，它的前一个点 `p` 已经定型。`p` 定型时试过 `p→x`，因此 `l(x)` 不大于假想路径到 `x` 的前缀长度。又因为余下的边权非负，前缀不会比整条路长。于是 `l(x) ≤ 前缀长度 ≤ 假想路径总长 < l(u)`，与 `u` 是未定型点中标号最小的矛盾。

负边破坏的正是「前缀不比整条路长」。例如有向边 `s→u:2`、`s→x:5`、`x→u:−4`，算法会先定型 `u=2`，但经 `x` 实际只要 1。这张图甚至没有环，所以「没有负环」也不够。

### 教材例 3.4.1：终点第一次有标号时不要停

用图 3.4.2 从 `a` 求到 `z`。表中只列每一轮变小的标号：

| 本轮定型 | 本轮松弛成功的标号 |
|---|---|
| `a=0` | `b=4, c=2` |
| `c=2` | `b=3, d=10, e=12` |
| `b=3` | `d=8` |
| `d=8` | `e=10, z=14` |
| `e=10` | `z=13` |
| `z=13` | 终点已定型；按前驱倒推为 `z←e←d←b←c←a` |

最短路径是 `a→c→b→d→e→z`，总长 `2+1+5+2+3=13`。第一次更新 `z` 得到 14，只说明找到了一条路。若只求 `z`，必须等它**被选为最小并定型**才可结束。教材式实现每轮扫描顶点找最小，配合矩阵做更新，时间 `O(n²)`；用最小堆加速取最小不会改变证明或定型条件。

## 4. 匈牙利算法：怎样判定换几条边真的能多配一对？

教材 §5.4 讨论无权二部图 `G=(V₁∪V₂,E)`，边只在两部之间。**匹配** `M` 是一组没有公共端点的边；端点被 `M` 中的某条边覆盖，称为 `M` 饱和点。求**最大匹配**就是让 `|M|` 最大，不是求总权最大的指派。再添不进一条边的匹配只叫**极大匹配**，可能还可以通过换边扩大。

### 交错不一定能增广

关于 `M` 的**交错路**，是匹配边和非匹配边交替出现的路。若两端都不饱和，它就是 **`M` 可增广路**：第一条和最后一条必为非匹配边，因此非匹配边比匹配边多一条。把路上的边成批翻转，也就是作对称差 `M ← M ⊕ E(P)`。内部点各失去一条旧边、各得到一条新边，两端各获得一条新边，路径外的匹配不动；仍然是匹配，而且 `|M|` 恰好加 1。如果只翻转一条两端不满足条件的交错路，就没有这个保证。

### 教材的 `S`、`T` 分别在记什么？

从任意初始匹配开始（也可以为空）。若 `V₁` 全部饱和，已经达到上界 `|V₁|`。否则在 `V₁` 取一个未检验的非饱和点 `x` 作根：

1. 置 `S={x}`、`T=∅`。`S` 记录交错搜索已经到达的左侧点，`T` 记录已经检查且饱和的右侧点。`N(S)` 是 `S` 内各点在右侧的邻居并集。
2. 从 `N(S)−T` 选一个右侧点 `y`。若 `y` 未饱和，就按搜索时记下的来路得到 `x` 到 `y` 的可增广路，翻转后回到外层继续。若 `y` 已与 `u` 匹配，把 `y` 加入 `T`、把 `u` 加入 `S`，继续找。
3. 若 `N(S)=T`，这个根不能增广。教材第 144 页正文说明还要检验其他未饱和根；不能因一个根无路就断言整个匹配已最大。

为什么 `S` 连向 `N(S)−T` 的边都不是匹配边？根 `x` 未饱和；其余左点进 `S` 时，它所匹配的右点已经进 `T`。因此搜索确实在交替地「从左沿非匹配边到右，再从右沿匹配边到左」。失败时，`T` 通过匹配恰好对应 `S` 除根以外的点，于是 `|N(S)|=|T|=|S|−1`。这一组左点本来就不能全配上。后续通过增广改进时，已饱和的点仍然饱和，这组里仍只有 `x` 未饱和，因此不必重新检验这个失败的根。

### 教材例 5.4.1：从三对增到四对，再证明不能到五对

图 5.4.2 初始 `M={x₂y₂,x₃y₃,x₅y₅}`。从 `x₁` 走非匹配边到 `y₂`，沿匹配边回到 `x₂`，再到未饱和的 `y₁`，得到 `x₁—y₂—x₂—y₁`。去掉 `x₂y₂`，加入 `x₁y₂,x₂y₁`，就有四对。剩下的非饱和左点是 `x₄`。从它搜索，最后得到 `S={x₄,x₁,x₃}`，`N(S)=T={y₂,y₃}`。这三个左点只有两个右邻居，所以不可能出现覆盖全部五个左点的匹配；已有四对就是最大。

### 为什么「没有可增广路」能证明最大？

若另有一个更大的匹配 `M′`，只看 `M` 与 `M′` 不同的边。任一点最多连一条 `M` 边和一条 `M′` 边，所以这些边分解成交替的路径或偶圈。偶圈中两种边一样多；因为 `M′` 总边数更多，至少有一条路径首尾都是 `M′` 边，较 `M` 边多一条。它的端点在 `M` 中未饱和，正是关于 `M` 的可增广路。于是找尽所有可能的根仍无增广路，就排除了更大的匹配。教材按边比较次数给出 `O(nm)` 的复杂度：一轮搜索最多比较 `m` 条边，增广或检验一个失败根的轮数合计为 `O(n)`。

## 5. 顺序着色法：得到三色方案，能说图的色数就是三吗？

正常顶点着色要求简单无向图中，**每条边的两个端点颜色不同**。图的色数 `χ(G)` 是所有合法着色中最少使用的颜色数。顺序着色法的输入除了图，还有一个顶点次序；它输出按这个次序得到的方案。这个方案的用色数可以给 `χ(G)` 一个上界，不当然等于 `χ(G)`。

### 每个点从色号 1 试起

教材用 `N(xᵢ)` 表示顶点 `xᵢ` 的邻点集，用 `π(xᵢ)` 表示它的颜色。按给定次序取下一个 `xᵢ`，只看 `N(xᵢ)` 里**已经着色**的点。从色号 1 往上试，找第一个未被这些邻点用过的色号。不必回头改色，也不必为没着色的邻点预留颜色。

为什么这样一定合法？对于任意边 `uv`，后着色的端点会把先着色端点的颜色列为禁用色。为什么一定有色可选？若一个点有 `d` 个邻点，至多禁用 `d` 种颜色；在 `1,…,d+1` 里总有一个可用。教材定理 6.5.6 由此得到全图至多用 `Δ(G)+1` 色，`Δ(G)` 是最大顶点度。这是顺序着色的上界，不是最优性定理。

### 教材例 6.5.6：为什么这里确实需要三色？

图 6.5.8 按从上到下、同一行从左到右的次序演示了图 6.5.7。七个顶点依次取 `1,2,1,2,3,1,2`。第 5 步处理左下点时，第二行的中点已涂成 1，左右两点已涂成 2，这些都是它的邻点，所以它是第一个需要取 3 的点。

要证明这里 `χ(G)=3`，还需说明两色不够。第二行左点、第二行中点、左下点在图中两两相邻，构成三角形，每点必须异色。这给出下界 3；再与图上合法的三色方案合起来，才能得到等号。

### 换个次序，哪里会多用一种色？

看四点路径 `a—b—c—d`。按 `a,b,c,d` 着色，四点交替取 `1,2,1,2`。按 `a,d,b,c` 着色，`a,d` 不相邻，都先拿 1，随后 `b` 拿 2。最后 `c` 的两个邻点 `b,d` 分别拿了 2、1，只好拿 3。同一个图用过三色，并不妨碍它有两色解。这是因为算法不回头重涂，不是约束变多了。

用邻接表统计禁用色，并从 1 找第一个可用色，单点最多检查其度数加一的色号；若禁用标记可按轮复用，不必每轮清空大数组，总时间可做到 `O(n+m)`。

<a id="preorder"></a>
## 6. 前序遍历算法：为什么是根、整棵左子树、整棵右子树？

教材 §3.3 说，遍历一棵根树就是**每个结点恰好访问一次**。二元有序树中，每个结点有左、右两个位置，各自都可以为空。左右是结构信息，不要求结点数据满足大小关系。「访问」是访问到结点时做一次的操作，比如输出符号；至于输出什么，不影响该到哪个结点。

### 把遍历一棵树拆成两个更小的同类问题

```text
Preorder(u)：
    若 u 为空，返回
    访问 u
    Preorder(u 的左孩子)
    Preorder(u 的右孩子)
```

根先访问，再把同一个问题交给左子树。左边还没全部返回时，父结点的右递归还没开始。访问叶子后返回的是最近的调用，所以右边何时开始，不需要额外写规则。可用结构归纳说明正确性：空树不用访问；非空树由根与两棵互不重叠的子树组成，假定两棵更小的子树分别遍历一次，那么整棵树的每个结点也恰好访问一次。

同一棵树，**前序、中序、后序**的区别在于访问根放在哪一步：根在左子树之前、两棵子树之间、或右子树之后。它们都先递归左子树再递归右子树，不像层序那样先访问完一整层。

### 教材例 3.3.8：用表达式树走一遍

教材图 3.3.13 的根是减号，左子树代表 `((a+b)*c)*(d+e)`，右子树代表 `f-(g*h)`。内部结点是运算符，两个孩子分别是左右操作数：

| 当前范围 | 按前序读出的符号 |
|---|---|
| 根 `-` | `-` |
| 整棵左子树 | `* * + a b c + d e` |
| 整棵右子树 | `- f * g h` |

拼起来是 `- * * + a b c + d e - f * g h`，也就是前缀形式。走到最左边的 `+` 时，要先访 `a` 再访 `b`，回到它上面的乘法调用后才轮到 `c`。返回某个调用不会再次输出那个结点。试着遮住右子树那一行：为什么读到 `f` 前已经输出过右子树的减号？因为到任何子树时，规则都是先访问它自己的根。

每个结点处理一次，若一次访问的工作是常数，时间 `O(n)`；不计输出，调用栈占 `O(h)`，`h` 是最长根到叶路径上的结点数。树长成一条链时 `h=n`，不一定是 `log n`。

## 附：六个网页案例分别把什么变成了图？

这一节只说明展示与教材算法的对应关系。网页上的场景名称、颜色和回放都不参与算法定义。需要看按钮怎么操作时，再翻 [README 的演示表](../README.md#六个场景怎么演示)。

| 展示案例 | 建模与现场改参 | 用教材原理解释结果 |
|---|---|---|
| 社交消息触达 | 人是顶点，允许直接转发是有向边；停用转发关系就是删边。 | Warshall 求可达矩阵；选发布者就是读那一行。沿别的路仍可到达的人，不会因为一条边删除就一定收不到。 |
| 配送巡回 | 仓库和选中的门店构成带权完全图，站间距离是边权；加入自提点就是加入一个要访问的顶点。 | 从当前站重选最近的未访问点。新站改变后面的顺序，甚至可能让本次贪心算出的总里程下降；这不代表多一站的最优解更短。 |
| 城市交通 | 路网节点和可通行方向构成有向图；封路删除可走的边，换策略改变边权。 | Dijkstra 最小化本次选定的累计边权。最终路线走的是前驱链，不是把所有定型过的点串起来。 |
| 岗位分配 | 志愿者和岗位在图的两部，资格是边；取消某人某岗资格就是删边。 | 按编号看哪条增广路让多人换岗、总数却恰好加一；取消唯一直播资格后，直播岗没有邻点，最多只能排七岗。 |
| 地图着色 | 区域是顶点，共用一段边界才连边；交换 I、J 只改变顶点处理次序。 | 顺序着色的禁用色取决于已经着色的邻点。得到 4 色或 5 色都是方案，不等于证明了这张图的色数。 |
| 目录检索 | 目录组织成二元有序树；选起始目录就是换一棵待遍历的子树。 | 前序遍历决定目录访问顺序，关键词只决定访问时记不记下某个文件。改关键词不剪枝，改起始目录才改变访问范围。 |
