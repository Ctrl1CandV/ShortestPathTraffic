# 确认单：六个图论算法课堂演示

日期：2026-11-26　状态：用户已确认开工

## 一句话目标

老师能在同一个离线网页中任选一个场景，现场改变输入、看到算法重新计算；随机抽到的组员能结合图上的一步和教材对应页，解释怎么算、为什么这样算、结果能保证什么。

## 项目档位

- 规模：在现有交通项目中扩展五个小场景，统一入口、测试和讲义，作为一轮课程作业交付。
- 寿命：短期课堂展示，不另建长期平台。
- 交给谁：图论课程小组用于演示，全体成员备抽查，老师可当场操作。
- 验证档位：六种算法各用手算例和边界自动化验证；六个场景逐个在浏览器操作，不以界面有按钮代替验证。

## 使用者与任务

组员按 README 启动本地服务，直接切到被抽中的场景。先解释图的点、边或权重表示什么，再改一个有实际意义的输入，看计算步骤和结果，最后说明一种该算法不能回答的问题。

## 倾向

- 想要：沿用现有本地 Python 服务、原生网页、中文控件和真实城市路网。保留当前未提交的五场景界面和讲义草稿作为可核对、可补全的素材。
- 不要：新框架、云服务、六套启动命令、每场景多算法对照，或只能切换预先写好的答案。旧版双算法交通项目保留在 Git 历史（本轮之前为 `ea02a1c`）。

## 功能与架构

每个场景恰好一种教材算法；下表为已查看的教材原页。印刷页以书页为准，PDF 页从 1 起数。场景名称是应用题，不声称书中使用了相同的故事或样本数据。

| 场景与唯一算法 | 印刷页 / PDF 页 | 改什么 → 看什么 |
|---|---|---|
| 社交消息转发 · Warshall 算法 | 15–16、54 / 21–22、60 | 编辑有向转发关系，选发布者 → 看可达矩阵、可收到消息的人（不含发布者）及中介轮次。|
| 配送巡回 · 最邻近方法 | 100 / 106 | 增减当天要送的站点 → 看每次选中的最近未访站、回仓路线和含回程的总里程。完全图的教学模型，非一般图的哈密顿回路判定，也不保证最短。|
| 城市交通 · Dijkstra 算法 | 89–90 / 95–96 | 选城市、起终点、权重，指定封路、恢复或导入城市包 → 看真实搜索、绕行和代价。三种权重是同一算法的不同输入；正式页面及其请求不运行或展示 A* 对照。|
| 志愿者岗位分配 · 匈牙利算法 | 144–145 / 151–152 | 修改人员的岗位资格 → 看增广路如何改派、最终配对及人数。目标是无权二分图最大匹配，不是最小成本指派。|
| 地图制作 · 顺序着色法 | 175–176 / 182–183 | 更换区划或改变地区上色顺序 → 看相邻约束、每区色号及本次用色数；不承诺最少颜色。|
| 二叉目录检索 · 前序遍历算法 | 84–85 / 90–91 | 选择从哪个目录开始、输入关键词 → 看根左右的访问顺序、范围和命中文件；不把普通目录树当作二叉搜索树。|

- 做：输入一变就用当前数据重算，或明确提示需重新搜索；只回放与本次计算对应的步骤。支持回到已知示例，便于下一位组员开讲。
- 不做：为五个小场景分别建设真实数据采集、文件导入或大型地图。没有真实来源的图和距离标明是教学样例。
- 数据：交通沿用本地城市包和署名；另外五项使用规模足以手算的本地数据，允许自由组合输入，而非只提供六段动画。
- 运行与部署：在 `ShortestPathTraffic/` 执行 `python -B app.py` 后从一个本地地址进入六项；课堂无需安装前端工具或联网。

## 内容与展示

页面以当前场景的图、参数、结果和实际计算步骤为主，不把讲义长文搬进操作区。保留交通封路、城市包导入和回放；五个新场景支持逐步解释中间状态。交付一份 [六个算法课堂讲解](../六个算法课堂讲解.md)，每节先给能直接开口的简短提纲，再给教材位置、图模型、伪代码、手算、正确性或可行性、复杂度与适用边界、现场操作和追问。示例数字在实现后重算核对。

## 审美

- 风格与参考：沿用现有交通页的浅色中文桌面界面，为课堂投影设计。当前节点、选中边和结果既有颜色，也有文字、色号或线型提示。
- 精致程度：五个新场景允许简单；优先让学生看得清一次选择、让老师找得到改参入口。
- 交给：整体导航与页面职责用 product-design，网页实现与实屏检查用 frontend-craft；核心逻辑用 tdd，交付按 dev-acceptance 核对。

## 假设与“你定”的选择

## 验收结果

### 当前版本：投影用较大实例，手算留在自学笔记

根据后续反馈，交通不变；另外五项不增加操作流程，改为打开就展示较大的实例。讲义由抽讲稿改为给组员自己读的算法设计笔记。下面是开发者在浏览器里对当前默认输入的实测；原小图的结果作为历史记录保留，不再用于核对默认页。

| 当前场景 | 改一个输入的结果 |
|---|---|
| 社交 | 三个社团 15 人；断开陈曦→周宁，安然触达 14→4；启用杜若→唐棠恢复为 14。 |
| 配送 | 西侧仓库默认送 12 站，加临时自提点后改走西门店→临时自提点→社区站，总里程 126.9→123.3 km。 |
| 分配 | 八人八岗，第 8 步沿七人增广路完成排班；去掉小陶的直播资格只能排 7 岗。 |
| 区划 | 十五区、30 对共边；交换 I/J 顺序后 4→5 色。原四区手算模板仍可切换，ABCD/ADBC 分别用 2/3 色。 |

复验命令：`python -B -m pytest -q -p no:cacheprovider`（43 项通过），`node --test tests/algorithms.test.mjs`（8 项通过）。第二轮新增三个穷举对照：4,096 张四点有向图与逐点遍历对比可达矩阵；65,536 种 4×4 资格表与枚举分配对比最大人数；64 张四区图的全部 24 种次序逐步核对最小可用色。对照算法只在测试中运行。启动与现场操作见仓库 README。未在实际教室投影仪或断开物理网卡的条件下测试。导入测试结束后已移除济南的本地测试副本，保留 `examples/jinan.json` 供现场演示。

第二轮复查重做了 A1–A9 的浏览器操作，结果与上表一致。另订正了三处讲解口径：路网定型节点不等于沿途路口；Warshall 的传递闭包与允许零长路的可达矩阵对角线初值不同；只送一个站点是往返配送，不称简单图中的哈密顿圈。补写了搜索后需重新打开道路编辑区才能恢复该段的步骤。
